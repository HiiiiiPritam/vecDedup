The problem

Vector databases are re-snapshotted constantly: nightly backups, re-embeds, A/B experiments on a new model. Each snapshot is a multi-GB blob of float vectors and an HNSW graph. Generic dedup (zstd, rsync, content-defined chunking) works on bytes: floats look like random noise to it, and one changed vector or a reordered file defeats it.

The idea

1. Segment by vector id. Vectors are grouped by stable id (256 consecutive ids per segment), so row order, compaction and shuffling don't matter. Each segment is hashed (SHA-256) and stored in a content-addressed store; unchanged segments are never rewritten.

2. Delta-encode changed segments. A changed segment is stored as a byte-shuffled XOR against its parent version, then zstd. Re-embedding noise shares exponent bits, which collapses to near-nothing.

3. Snapshot the HNSW graph too (TGIS). Graph segments are stored as edge deltas (ΔE+ / ΔE−) against the previous snapshot, and the index is updated incrementally (insert / delete+repair), so a 1% churn touches ~19% of nodes, not 100%.

4. Merkle trees over segments let integrity checks and change detection skip any identical subtree by comparing a single hash.

5. Optional semantic (lossy) mode. Residual product quantisation with a drift-aware codebook: 10–80× smaller at a chosen recall.

What this demo is

This page is a thin UI over the same Go packages the CLI and benchmark harness use (internal/repo, hnsw, quant, segment, cas), with real data on disk. Nothing is mocked. Build & run: go run ./cmd/vddemo
